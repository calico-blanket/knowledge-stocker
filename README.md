# knowledge-stocker（ナレッジ保存）

気になった記事を、Androidの共有シートから **3タップ** でGoogle Driveにカテゴリ別ストックできるPWAです。
保存先がGoogle Drive/Sheetsなので、AI（Claude等）からも直接参照できます。

**操作の流れ（実機）**
1. ブラウザの共有ボタン（⤴）をタップ
2. 共有先から「ナレッジ」を選択
3. カテゴリボタンをタップ → 自動保存 → 画面を閉じる

保存されるもの:
- 検索用インデックス: `マイドライブ/ナレッジ/ナレッジ一覧`（Googleスプレッドシート）に、保存の都度「日時・カテゴリ・タイトル（クリックで記事を開けるリンク付き）・URL・メモ・タグ」を1行追記
- 過去にGoogleドキュメントとして保存した記事がある場合は、Driveの「ナレッジ」フォルダから直接開けます（編集画面から本文の再編集も可能）

> 共有元が短縮/リダイレクトリンクを渡してきた場合は、保存前に実際の記事URLへ自動解決してから保存します（元の短縮URLは「共有時のURL」として参考記録）。

## 構成

| レイヤー | 実体 | 役割 |
|---------|------|------|
| フロントエンド | `index.html` + `manifest.json` + `sw.js`（PWA） | Web Share Target APIで共有シートに登録。カテゴリ選択・一覧閲覧・カテゴリ管理UI |
| バックエンド | `gas/Code.gs`（GAS Webアプリ） | タイトル自動取得・Sheetsインデックス追記・カテゴリ管理API |
| ホスティング | Vercel（静的配信） | PWAはHTTPS配信が必須のため |

```
knowledge-stocker/
├── index.html            # PWA本体（1枚のHTML）
├── manifest.json         # share_target 定義を含むPWAマニフェスト
├── sw.js                 # サービスワーカー（インストール要件用の最小実装）
├── icons/                # アプリアイコン（scripts/generate_icons.js で生成）
├── gas/
│   ├── Code.gs           # GASバックエンド（GASエディタに貼り付けて使う）
│   └── appsscript.json   # OAuthスコープ等の設定（参考。GASエディタでは通常直接編集しない）
├── scripts/
│   ├── generate_icons.js # アイコン生成（Node組み込みのみ）
│   └── dev_server.js     # ローカル動作確認用サーバ
└── test/                 # 自動テスト（node --test）
```

## 認証について

このアプリはGoogle OAuthクライアントを使いません。代わりに、GAS側のスクリプトプロパティ
`SHARED_TOKEN`（合言葉）と、PWA設定画面に入力する値を一致させる簡易認証方式です。
GCPプロジェクトの作成やOAuth同意画面の設定は不要です。

## セットアップ手順

このリポジトリをフォーク／クローンしたら、以下の順に自分のGoogleアカウントで環境を作ります。

### Step 1: 検索用インデックス（Googleスプレッドシート）を作成

1. [sheets.google.com](https://sheets.google.com) で新しいスプレッドシートを作成（名前例: ナレッジ一覧）
2. 「拡張機能」→「Apps Script」を開く（このスプレッドシートにコンテナバインドされたGASプロジェクトが作成されます）

### Step 2: GAS（バックエンド）のデプロイ

1. Step 1で開いたエディタで、最初から入っている `function myFunction() { }` を**全て削除**してから、
   このリポジトリの [gas/Code.gs](gas/Code.gs) の内容を貼り付けて保存（Ctrl+S）
   - ⚠️ よくある失敗: デフォルトの `myFunction` の中括弧 `{ }` の**内側**に貼り付けてしまうと、
     `doGet`/`doPost` が正しく認識されません。貼り付け後、関数選択のプルダウンに `doGet` `doPost`
     が並ぶか確認してください
2. 合言葉を設定する（推奨。URLを知られても第三者に書き込まれないための簡易保護）
   - 左メニュー「プロジェクトの設定」→「スクリプト プロパティ」→「プロパティを追加」
   - プロパティ: `SHARED_TOKEN` ／ 値: 好きな合言葉（例: ランダムな英数字）
3. 右上「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**（合言葉で保護する前提。Googleアカウント制限にするとPWAからのfetchが通らないため）
4. 「デプロイ」を押し、権限承認ダイアログで**「Select all」にチェックして**承認
   - 要求される権限: Google Driveへのフルアクセス（過去記事の参照用）、Sheetsへのアクセス（インデックス追記）、
     外部サービスへの接続（記事タイトル取得）
5. 表示された **WebアプリURL**（`https://script.google.com/macros/s/…/exec`）を控える

動作確認: WebアプリURLをブラウザで開き `{"ok":true,...}` が表示されればOK。

> コードを修正したら「デプロイ」→「デプロイを管理」→ 鉛筆アイコン → バージョン「新バージョン」で更新する（URLは変わらない）。

### Step 3: PWA（フロントエンド）のVercelデプロイ

1. このリポジトリを自分のGitHubアカウントにフォーク（またはこのコードで新規リポジトリを作成）
2. [vercel.com](https://vercel.com) にGitHubアカウントでログイン
3. 「Add New…」→「Project」→ フォークしたリポジトリを選択
4. Framework Preset は「Other」のまま、設定変更なしで「Deploy」（ビルド不要の静的サイト）
5. 発行されたURL（`https://….vercel.app`）を控える

> 以後は `main` にプッシュするたび自動デプロイされます。

### Step 4: 実機（Androidスマートフォン）でのインストールと共有シート登録

1. Chromeで Step 3 のURLを開く
2. 初回起動時に設定画面が出るので入力して「保存する」
   - GAS WebアプリのURL: Step 2 で控えたURL
   - 合言葉: Step 2 で設定した値
3. Chromeのメニュー（⋮）→「**ホーム画面に追加**」→「**インストール**」を選択
   - ※「ショートカットを追加」ではなく「インストール」であること。インストール型で入れると共有シートに登録される
4. インストール後、適当な記事ページで共有ボタン（⤴）→ 共有先一覧に「**ナレッジ**」が出ることを確認
   - 出ない場合: 一覧を左にスクロール／「その他」を開く。それでも無ければ一度アプリを開いてから再確認

### Step 5: カテゴリを追加する

初期状態ではカテゴリは0件です。設定画面（⚙）の「カテゴリ管理」から、自分の使い方に合わせて
自由にカテゴリを追加してください（後から追加・削除・並び替えができます）。

### 実機での投稿テスト

1. Chromeで任意の記事を開く → 共有（⤴）→「ナレッジ」
2. 画面上部に「検出したタイトル（参考）」と保存対象のURLが表示されることを確認
3. カテゴリボタンをタップ
4. 「保存しました！」表示を確認
5. Googleスプレッドシート「ナレッジ一覧」に1行追記されていることを確認

## 画面の機能

| ヘッダーアイコン | 機能 |
|---|---|
| 📁 | Driveの「ナレッジ」フォルダを新しいタブで直接開く |
| 📋 | カテゴリ別の保存済み記事一覧を表示（タップで元記事を新しいタブで開く／各記事の「編集」でタイトル・URL・メモを修正／タグを設定した記事は一覧にタグバッジを表示） |
| ⚙ | GAS接続設定・カテゴリの追加/削除/並び替え |

### PCブラウザからの利用
Androidの共有シート（Web Share Target）はPCでは機能しないため、PCでは共有パラメータ無しで開いたときに表示される**URL・メモの手入力欄**から新規保存します。カテゴリ選択・一覧閲覧・記事編集はスマホと共通で、画面幅が広いときはレイアウトが横長向けに調整されます。

## カテゴリの管理

カテゴリは固定配列ではなく、GAS側のスクリプトプロパティで動的に管理しています（PWAは起動時にGASから取得）。

- **初期値**: 0件（空）。設定画面（⚙）の「カテゴリ管理」から自由に追加していく運用です
- **追加・削除**: 設定画面（⚙）の「カテゴリ管理」から行えます。コード変更もGASの再デプロイも不要です
- **並び替え**: 設定画面（⚙）の「カテゴリ管理」の ↑/↓ ボタンで表示順を変更できます
- **削除の挙動**: カテゴリ選択肢から外れるだけで、Sheetsの過去の行は削除されません（非破壊）
- **改名は未対応**: 名前を変えたい場合は「新しい名前を追加」→「古い名前を削除」で代用してください

## ID列のマイグレーション（既存シートの移行手順）

各記事の行を一意に識別するための **`ID` 列**（UUID）が追加されました。
これにより、Googleドキュメントを持たない新規保存の記事も編集できるようになります。

すでにこのアプリを使っていて記事が保存済みの場合、以下の手順で移行します。
**まだ一度も保存していない場合は、何もする必要はありません**（新規シートには最初からID列が作られます）。

> ⚠️ **これはスプレッドシートの列構成を変える破壊的な変更です。**
> 作業前に必ずバックアップを取ってください。

### 手順

1. **バックアップ（必須）**
   対象のスプレッドシートを開き、「ファイル」→「コピーを作成」でコピーを保存します。
   何か問題が起きたときは、このコピーから元のデータを復元できます。
2. **GASを更新する**
   [gas/Code.gs](gas/Code.gs) の最新版をGASエディタに貼り付けて保存し、
   「デプロイ」→「デプロイを管理」→ 鉛筆アイコン →「バージョン」を**新バージョン**にして「デプロイ」します。
   （既存のデプロイを編集してください。新規デプロイにするとWebアプリURLが変わります）
3. **一覧を1回開いて移行を発火させる**
   PWAでいずれかのカテゴリの記事一覧を開きます。このとき既存の全行に自動でUUIDが振られます。
4. **確認する**
   スプレッドシートの `ID` 列（H列）に、各行の値が入っていることを確認します。
   一覧をもう一度開き直しても**ID列の値が変わらない**ことも確認してください（移行は何度実行しても安全です）。

### 移行の性質

- **冪等**: 値を書き込むのは「ID列が空の行」だけです。すでに値がある行は型（文字列・数値）を問わず変更しません。何度実行してもID列の内容は初回実行後から変わりません。
- **非破壊**: 行の追加・削除・並べ替えは行いません。既存の列（日時・カテゴリ・タイトル・URL・メモ・Driveファイル・タグ）の位置も変わりません（ID列は末尾に追加されます）。
- **旧データとの併存**: 移行前に保存した記事は `ID` と `fileId` の両方を持ちますが、編集時は `id` が優先されます。ID列を持たない状態の記事も、`fileId` があれば従来どおり編集できます。

### ロールバック手順

移行後に問題が起きた場合は、以下のいずれかで元に戻せます。

- **方法A: バックアップから戻す（推奨）**
  手順1で作成したコピーを開き、「ファイル」→「コピーを作成」で作業用に複製するか、
  コピー側のシート内容を元のスプレッドシートに貼り戻します。
- **方法B: ID列を削除して旧バージョンのGASに戻す**
  1. スプレッドシートの `ID` 列（H列）を右クリックして「列を削除」
  2. GASエディタで**この変更より前のバージョンの `Code.gs`** を貼り付けて保存
     （GASエディタの「デプロイ」→「デプロイを管理」から以前のバージョンを選び直すこともできます）
  3. 旧バージョンは `fileId` を編集キーにするため、Googleドキュメントを持たない記事は編集できない状態に戻ります（データ自体は失われません）

## 設計メモ

- **認証**: GASは「全員」公開 + スクリプトプロパティ `SHARED_TOKEN` の合言葉照合による簡易保護（本格的な認証基盤は意図的に持たない）。保存・カテゴリ変更(POST)だけでなく、**記事一覧・カテゴリ取得(GET)も合言葉必須**（一覧はタイトル・URL・メモといった閲覧記録に近い情報を含むため、WebアプリURLを知られただけでは読めないようにしている。稼働確認のみ合言葉不要）
- **CORS**: PWA→GASの通信は、POSTは `Content-Type: text/plain` で送ることでプリフライト(OPTIONS)を回避し（GASはOPTIONSに応答できない）、GETはヘッダを付けないシンプルリクエストとして送る
- **URLの受け取り**: Androidの共有シートはアプリによってURLを `url`/`text`/`title` のどこに入れるかが揺れるため、`shared_url` → `shared_text` → `shared_title` の順で探索
- **タイトル取得のフォールバック**: 通信失敗・HTTP 4xx/5xx・`<title>` 不在時は og:title → URLそのもの、の順で代替
- **検索用インデックス（Sheets）**: タイトル列は元記事URLへの `HYPERLINK` 数式にしており、Sheets上でタップすると開く
- **カテゴリのCRUD・並び順**: `PropertiesService`（スクリプトプロパティ）にJSON配列として保存（配列の順序＝表示順）
- **行一意ID（ID列）**: Sheetsインデックスの末尾に `ID` 列を持ち、1行=1記事をUUIDで一意に識別する。新規保存時に必ず発行し、ID列が空の既存行には一覧取得時に自動で発行される（→「ID列のマイグレーション」）
- **保存済み記事の編集**: `action=update`（POST・`SHARED_TOKEN`検証あり）で Sheetsインデックスの該当行（タイトル/URL/メモ）を更新する。行の特定キーは **`id`（ID列のUUID）優先・`fileId`（GoogleドキュメントのID）フォールバック**。`id` 指定時はSheetsのみ更新（新規保存の記事はGoogleドキュメントを持たないため、Doc操作はスキップ）、`fileId` のみ指定時は従来どおりドキュメント本文も更新する。行特定は**Sheetsインデックスに載っている記事に限定**し、無関係なDriveファイルを触らせない
- **保存の体感高速化（fire-and-forget）**: GAS側のタイトル取得は数秒〜数十秒かかるため、PWAは応答を待たずに送信した時点で「保存しました」を表示する。fetchの `keepalive: true`（非対応環境は `navigator.sendBeacon`）により、表示直後にアプリを閉じても送信はOS/ブラウザが完了させる
- **表示キャッシュ（stale-while-revalidate）**: カテゴリ一覧と記事一覧を `localStorage` にキャッシュし、画面表示時はまずキャッシュで即描画→裏でGASから最新を取得して差分があれば描き直す
- **記事一覧のページング**: 一覧APIは新しい順に50件ずつ返し（`offset` パラメータで続きを取得、`hasMore` で継続有無を返す）
- **短縮/リダイレクトURLの解決**: 保存前に `UrlFetchApp`（`followRedirects: false`）で3xxレスポンスの`Location`ヘッダを最大5回まで手動で辿り、実際の記事URLを特定する
- **Sheetsへの書き込み安全策**: タイトル・メモ等の自由入力由来のセル値は、先頭が `=` や `+` の場合にアポストロフィを付けて書き込む（数式インジェクション対策）
- **一覧画面のXSS対策**: 記事一覧はHTML文字列の結合ではなくDOM API（`createElement` + `textContent`/`href`プロパティ）で描画する
- **メモの重複防止**: 共有テキストの「URL以外の部分」がタイトルと同一の文字列になることが多いため、GAS側で実際に取得したタイトルと完全一致する場合はメモとして保存しない
