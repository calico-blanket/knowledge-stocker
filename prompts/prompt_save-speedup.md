# 記事保存アプリの高速化・改善(4項目)

`.claude/fable.md` の実行規律に従うこと。
進捗報告は要点のみ。コードの全文再掲は変更箇所に限る。

## 背景
記事保存アプリ(PWA + GAS)で以下の不満がある:
1. 保存に20〜30秒かかる(GASが全処理完了まで応答を返さないため)
2. 各画面のカテゴリー表示が遅い(特に起動時)
3. カテゴリーからの記事一覧の読み込みが遅い
4. カテゴリーの表示順を変更できない(新規登録が常に末尾)

## 改善1: 保存の体感高速化(fire-and-forget + keepalive)
- PWA側: 保存の fetch を応答待ちなしに変更し、送信直後に
  「保存しました」と表示する
- fetch には必ず `keepalive: true` を付ける(送信完了前に
  PWAが閉じられても送信がOSにより完了されるようにするため)。
  keepalive が使えない環境向けに navigator.sendBeacon への
  フォールバックも検討すること
- GAS側 doPost の処理内容は変更しない(サーバー側で従来どおり
  タイトル取得→Google Docs保存が完走する)
- 送信自体の失敗(オフライン等)は検知して「保存できませんでした。
  通信環境を確認してください」と表示すること

## 改善2: カテゴリー表示の高速化(キャッシュ)
- カテゴリー一覧を localStorage にキャッシュする
- 画面表示時はまずキャッシュから即座に描画し、裏で GAS から
  最新一覧を取得して差分があれば表示を更新する
  (stale-while-revalidate 方式)
- 初回起動などキャッシュが無い場合のみ取得完了を待つ

## 改善3: 記事一覧の読み込み高速化
- GAS側の記事一覧APIを確認し、不要な処理(本文取得など)を
  していれば一覧に必要な情報(タイトル・日付・ファイルID)のみ
  返すよう軽量化する
- 記事一覧もカテゴリー同様に localStorage キャッシュ +
  裏で更新の方式にする
- 件数が多い場合に備え、新しい順に一定件数(例: 50件)で
  区切る等の対策が必要か確認し、必要なら実装する

## 改善4: カテゴリーの表示順変更
- カテゴリー一覧画面に並び替え機能を追加する
  (スマホ操作前提のため、各カテゴリーに上へ/下へボタン、
  またはドラッグ&ドロップ。実装が確実な方を選ぶこと)
- 並び順は GAS 側(ScriptProperties または管理用シート)に
  保存し、全画面のカテゴリー表示に反映する
- 新規カテゴリーは従来どおり末尾に追加

## 制約
- 既存のカテゴリーフォルダID・保存形式(Google Docs)・
  保存済みファイルには影響を与えない
- claspを使っている場合は push まで、使っていない場合は
  変更後のGASコードと手動反映手順を提示する

## 完了条件
1. 共有→保存の体感が1〜2秒(送信直後にアプリを閉じても消失しない)
2. 2回目以降の起動でカテゴリーが即座に表示される
3. 記事一覧の表示が体感で明確に速くなる
4. カテゴリーの並び順を変更でき、変更が保持される
5. 修正内容をコミットし GitHub へ push する

## 検証
- 通常の記事URL、重いページ、存在しないURL、送信直後にアプリを
  閉じるケースの4パターンで保存結果を確認し、報告すること
- 並び替え後にアプリを再起動して順序が保持されることを確認すること
