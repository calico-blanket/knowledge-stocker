# 依頼: PCブラウザからの閲覧・保存・編集対応

## 背景
現状のPWA(`index.html`)はAndroidの共有シート(Web Share Target API)経由の投稿を前提に、
片手操作向けの最小UIで作られている(スマホ側の画面調整は直近で反映済み)。
これをPCブラウザ単体でも同等に使えるようにしたい。

## やりたいこと
1. **PCからの新規保存**
   - PCの共有シートはAndroidと仕様が異なり share_target が機能しないため、
     URL(+任意でメモ)を手入力できるフォームをPWA内に追加する。
   - カテゴリ選択は既存のボタンUIを流用してよい。
2. **一覧の閲覧**(既存の📋機能をPC幅でも問題なく使えるか確認・調整)
3. **保存済み記事の編集**
   - 現状GAS側に更新系のAPIが無いため、新規に action=update 相当を追加する必要がある。
   - 対象: Sheetsインデックスの該当行(タイトル/URL/メモ)、および対応するGoogleドキュメント本文。
   - Sheets側の行特定方法(現状は日時+カテゴリ等での突合が必要になる可能性)を検討し、
     実装前に方針をユーザーに1行で確認すること。
4. **レイアウト**
   - 現行のスマホ縦画面前提のCSSを、PC幅(横長)でも崩れず、かつスマホ側の見た目・操作性を
     劣化させない形でレスポンシブ対応する(メディアクエリでの分岐を基本とする)。

## 制約・注意点
- 既存のトークン認証(SHARED_TOKEN)・XSS対策(DOM API描画)・Sheets数式インジェクション対策
  (sanitizeCellText_)の方針は編集機能にも同様に適用すること。
- 既存のカテゴリ管理・Drive保存ロジック(Google Docs形式)は変更しない。
- 既存のnode --testによる自動テスト(GASロジック・クライアントロジック)に、
  追加した関数の分だけテストを追加すること。
- 進捗報告は要点のみ、コードの全文再掲は変更箇所に限ること。
- 直近のスマホ側UI変更(index.html)を上書きしないよう、着手前に現在のindex.htmlの
  差分内容を確認すること。

## 参照ファイル
- `.claude/fable.md`: 実行規律。本タスクは複数ステップの実装作業のため必ず適用する
- `.claude/LESSONS.md`: 特に「Phase 0の明文化を追加タスクで省略した」の教訓を踏まえ、
  着手前に必ずPhase 0(完了条件・検証方法・やらないこと)を3行で提示すること
- `README.md` / `gas/Code.gs`: 現行仕様(Code.gsはユーザー確認済みの最新版)

## 進め方
Phase 0の3行提示 → TodoWriteでのタスク分解 → 実装。
ブランチを切って作業し、完了時はPRを作成すること(mainへの直接pushはしない)。
実機(Android端末)側の動作に影響がないことも、既存のスマホ操作フローで確認すること。
