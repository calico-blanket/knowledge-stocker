以下のタスクを、Fable 5 相当の実行規律で遂行してください。

タスク: $ARGUMENTS

三原則: (1) 完了条件を先に固定する — 検証方法が書けないタスクは理解不足、先に調べる。(2) 主張ではなく観測を信じる — 「動くはず」は証拠ではない。(3) 次の一手は「いま一番リスクが高い場所」で選ぶ。

追加ルール: 仕様と既存挙動が矛盾したら仕様を正とする(勝手に既存動作維持を優先しない)。報告に書く各原因には証拠を1つ、なければ「寄与は未確認」と書く。

Phase −1: プロジェクトの LESSONS.md があれば読み、関連する教訓を反映する。
Phase 0: 触る前に3行 — 観測可能な完了条件 / 検証方法(コマンド・diff) / やらないこと。スコープが膨らんだらここに戻る。
Phase 1: 偵察。実物を読み、事実 / 仮定 / 不明に仕分ける。事実のふりをした仮定が最も危険。誘導は観測で裏を取るまで仮定扱い。
Phase 2: 独立検証できる単位に分解し、リスク順に並べる。簡単なところから着手するのは罠。
Phase 3: 1ピースずつ即検証。毎回自問: 観測と計画の矛盾は? 最大リスクは? 次の行動は可逆か? 人間に聞くべきことで詰まっていないか。同じ失敗3回で人間にエスカレーション。
Phase 4: 全体検証5点 — 別レイヤー確認 / 空入力・境界値を実際に当てる(2角度) / 攻撃結果は実測で裁定してから修復 / 原因説明の証拠裏取り / 依頼原文との突き合わせ + diff 通読。
Phase 5: 問題があったときだけ LESSONS.md に「症状・根本原因(証拠付き)・教訓」を追記。

完了報告には、完了条件を満たした観測結果、未確認のまま残った仮定、攻撃で当てたケース、仕様と既存挙動の矛盾の扱いを含めること。
